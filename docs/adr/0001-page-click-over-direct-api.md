# 0001 - 坚持页面内点击，而非直连价格接口

> **来源**: 本文件转自抓取源项目 (`qiandao`) 的 `docs/adr/0001-page-click-over-direct-api.md`, 正文保留原文未做改动——ADR 是历史决策记录, 改写会篡改记录。
>
> **用词映射**: 原文的「**分区**」即本项目的「**游戏**」。见 [CONTEXT.md](../../CONTEXT.md) 的用词映射说明。
>
> **状态**: 有效, 不可违背。

站点把左侧列表的价格数据放在一个形如 `/c2c-web/v1/common/currency-spu-price-list` 的 JSON 接口里，看起来完全可以用 HTTP 客户端直接请求——但**不能**。接口的真实域名是 `api.qiandao.com`（不是页面所在的 `qiandao.com`），且**必须携带页面内动态生成的 HMAC 签名头**（`x-request-sign`、`x-request-timestamp`、`x-request-package-id` 等），这些头无法脱离页面静态构造。实测在页面里用裸 `fetch` 绕过前端 axios 拦截器直接请求，返回的是 **HTTP 200 但 `items` 为空**；不在页面里则连签名都凑不出来。因此抓取**只能**走 Playwright 打开真实页面、模拟点击级联选择器。

## Considered Options

**直连接口（已否决）**。否决理由如上：签名头是站点约束，不是实现选择，绕过它的代价远超收益。

**页面内 `fetch`/`XHR` 注入（已否决）**。即使在页面上下文里调用，绕过 axios 拦截器就拿不到被注入的签名头，实测拿到空结果——**而且失败形态是 HTTP 200 + 空数组，不报错**，属于本项目最忌讳的静默错值。

## Consequences

- `package.json` 里声明了但从未使用的 `axios`，**不要**以「冗余依赖」为由删掉后顺手改成直连接口（源项目 `docs/产品说明.md` 7.8 曾建议移除该依赖，本条优先）。它更像是一个诱导下一个人重犯此错的路标。
- 抓取成本被页面加载与点击锁死——每个游戏至少一次 `goto` 加多次点击，无法靠并发请求优化。这是刻意的取舍，不是没优化。
- 站点的接口路径（`PRICE_API_PATH` / `CASCADE_API_PATH`）仍然是**等待逻辑的判据**，它们失效会导致抓取超时失败；这不改变「必须走页面」的结论。
