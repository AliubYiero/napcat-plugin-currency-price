# 0002 - 指令失败一律显式反馈，而非静默

## 背景与问题

[指令分发范式](../instruction-pattern.md) 的核心约束 3 规定：**权限不足与未知指令静默**（防权限探测），作用域不符回复提示。理由是——如果回复"权限不足"，攻击者可以通过枚举指令名，区分"指令存在但无权"与"指令不存在"，从而映射出插件的完整指令面。

本插件是运行在熟人小群与好友私聊里的价格查询工具。它的指令面里没有敏感操作：最"具破坏性"的不过是开关本群通知、订阅/退订某个游戏，二者都只影响操作者自己所处的会话。**探测这个指令面没有攻击价值**；而静默带来的代价是持续且真实的——用户打错字、拼错游戏名、没有权限时，得到的都是一片沉默，只能靠猜。

## Considered Options

**保持静默（已否决）**。范式默认策略。否决理由：防探测的收益在本插件里为零，可用性损耗却是每天都在发生的。而且"未知指令静默"还会掩盖一类真实故障——用户以为指令生效了，实际什么都没做。

**只对权限不足静默、其余回复（已否决）**。看起来是折中，但它把"防探测"这条理由保留了一半，却仍然无法抵挡枚举（未知指令回复本身已经暴露了指令是否存在）。既然防线已经撤了，保留一半只是让行为更难解释。

**三类失败一律显式反馈（已采纳）**。参数不合法、未知子命令、权限不足都回复固定格式的提示，且在文案里**如实区分**三者。

## 结论

分发层对三类校验失败一律回复：

```
{commandPrefix}: 非法参数 {出错的参数}      ← 参数不合法
{commandPrefix}: 未知指令 {整个参数串}      ← 未知子命令
{commandPrefix}: 权限不足 {整个参数串}      ← 权限不足
输入 '{commandPrefix} help' 获取帮助信息
```

要点：

- **文案如实区分，不统一成一句话**。既然回复本身已经放弃了防探测，统一文案就只剩下纯损失：一个没权限的用户看到"非法参数"会去检查拼写，而不是意识到"我没权限"。
- **前缀取自配置项 `commandPrefix`，不硬编码**。前缀是可配置的，硬编码会在用户改过前缀后误导人。
- **作用域不符仍按范式回复固定提示**（这条本来就不是静默的）。
