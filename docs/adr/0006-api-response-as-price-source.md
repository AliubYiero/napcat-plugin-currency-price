# 0006 - 列表页价格以接口响应为准，DOM 兜底

> **对应源项目决策**: 抓取源项目 (`qiandao`) 的 `docs/adr/0002-api-response-as-price-source.md`。本文件是它在插件语境下的版本——源项目是纯抓取脚本，插件多了配置、渲染与 WebUI，因此结论更细。
>
> **用词映射**: 源项目的「分区」即本项目的「游戏」，见 [CONTEXT.md](../../CONTEXT.md)。

**`price` / `unit` 曾经取自页面上价格区的文本**（`readCurrencyList` 读第一个 div，接口响应只拿来当"列表渲染完了没"的期望值）。现在反过来：**`prices[]` 的数值直接取自价格接口响应里的 `ratioPrice`**，页面文本只在该通货没出现在响应里时兜底。

这不违背 [ADR-0001](./0001-page-click-over-direct-api.md)——仍然是 Playwright 打开真实页面、点级联选择器，接口响应是从**页面自己发的那个请求**上拦下来的，不是我们构造请求直连。

## 背景与问题

页面上那一行显示的就是接口的这个字段，读文本是绕远路。三条具体理由：

- **读文本要先等 DOM 稳定**，而切区服时列表会先清空再重绘，中间态与残留值都真实出现过。接口响应本身就是"数据已到位"的信号，没有这段窗口。
- **区服归属由请求体里的 `specIds` 唯一确定**，比"页面看起来切过去了"更硬。⚠️ 代价是 `waitForResponse` **必须按请求体 `specIds` 匹配**，不能只按 URL——切区服时上一个区服的响应可能还在飞，只按 URL 会逮错，产出**归属正确、数值是隔壁区服**的错值。
- **原来的交叉比对守的是错的**。它拿 DOM 的 `元/个` 去比接口的 `rmbPrice`，那是**两个方向**的比对，正是元方向 4 位小数舍入误差的来源。同方向比对（`price` vs `ratioPrice`）没有这个问题。

## Considered Options

**维持 DOM 权威、接口只做交叉比对（已否决）**。它换来的是"和用户看到的一致"——可用户看到的就是这个接口给的数。代价是整套"等渲染稳定"的时序逻辑，以及上述那条错方向的比对。

**在页面内自己发请求（已否决）**。见 [ADR-0001](./0001-page-click-over-direct-api.md)，不重复。

**接口说无报价时改看页面（已否决）**。接口说"本区服无报价"（`ratioPrice` 为 `0`）时**不再看页面**。取舍理由与全项目一致：按接口记是**少一条数据**，按页面记是**多一条可能过期的数据**。

## 结论

**1. `price` / `unit` 取接口的 `ratioPrice` / 比率单位；该通货不在响应里时才退回页面文本。**

**2. `price` 的方向是「个/元」。** 本决策推翻 `design.md` §7.2 原有的示例（`{ price: 0.2444, unit: "元/个" }`）：主方向改为比率价，因为它**精度更高**（元价只到 4 位小数，比率价到 3 位以上且是接口原始值）。

**3. `rmbPrice` / `rmbUnit` 取自接口的 `rmbPrice`，走 DOM 兜底时取自页面第一行——两个来源都**不是** `1 / price` 算出来的。** 两个方向是**两个独立的事实**，不是精确倒数（见 [ADR-0005](./0005-order-book-capture-and-price-direction.md) 结论 2）。页面第一行显示的就是接口的这个字段，所以兜底路径的语义相同，只是精度降到页面的显示位数。读不到时两个键**一起不出现**（不产出"有价但没元价"的半条）。

**4. `price` 不再有 `0` 这个取值。** 接口的 `ratioPrice === 0` 即"本区服无报价"，落成 `null`。原 `design.md` §7.2 规则 3 里的「`0` = 页面确实报 `0`」在站点上没有对应形态——接口说 0 时页面显示的本来就是占位符，两者是同一件事。保留一个永不出现的值，只会让下游继续写 `price ?? 0` 这类把两者混起来的代码。

**5. `missing` 的口径随之改为「所有区服组合的价格接口响应里都没有这个 `spuName`」**，比原来的 DOM 名称匹配更硬（DOM 没匹配上可能只是选择器过期）。⚠️ 配套要求：`missing` 装满了清单里**全部**通货时记 `warn`——那更像"接口整体改版"而不是"N 个名字都拼错了"。

**6. `design.md` §8.3 的三条防线按新职责重排：**

| 防线 | 处置 | 理由 |
| --- | --- | --- |
| ① 页面级加载校验 | **保留** | 站点按 UA 拦截时页面是空壳 |
| ② DOM 与接口交叉比对 | **删除** | 它的职责是"DOM 读到的值可信吗"，而 DOM 已不是权威源；走兜底的那些通货恰恰是接口没给的，**没有接口值可比**。留着只会制造误判：接口说无报价、页面有残留旧值 → 判成"没渲染完" → **整个游戏本轮作废**（§8.3 的边界注记已踩过一次） |
| ③ 按位置而非颜色类定位价格行 | **保留** | 兜底路径仍按位置读 |
| 切区服后回读选择器 | **从判据降级为断言** | 归属已由请求体 `specIds` 确定；回读保留，用于在失败时给出更清楚的报错 |
| 等列表渲染 | **只在兜底路径上执行** | 主路径根本不读 DOM，也就不需要等 |

**7. 页面价格区的方向随之钉死**（源项目 `7e60963` 实测结论，两处相反）：

- **列表页**价格区第一行是 `1 <通货> = <值> 元`（元价），**第二行**是 `1 元 = <值> <通货>`（比率价）
- **挂单卡**读的是**第一行**，而那一行是 `1 元 = <值> 个`——**比率价方向**

因此列表页要改读**第二行**，`unit` 的拼法从 `quote/base` 变成 `base/quote`（`个/元`）。⚠️ 两行的 DOM 结构完全一样（都是 5 个 span、同样按位置取值），**读错行不报错、只静默换个方向**——所以纯函数层要加一条**形态守卫**：第二行的 `spans[1]` 必须是 `元`（第一行是 `spans[4] === '元'`），不通过记 `null` 并告警。

## 后果

- **抓取不再有"等渲染稳定"的时序依赖**。切区服后只要按 `specIds` 收到响应，数据即到位。
- **`price` 的数值带接口侧的舍入**（比率方向只到 3 位小数）。需要全精度时用 `detail.listings[].pricePerYuan`，那份来自详情接口的原始值。
- **DOM 兜底路径的定位收窄为"站点接口改版时的降级通道"**，它不再影响主路径的正确性，也因此会**很少被执行**——这类代码会腐烂，所以必须留在纯函数层并保住单测。
- **`missing` 的误报面变小**：名称匹配不再依赖 DOM 渲染。
- **`data.json` 需要升 `version`**（见 [ADR-0007](./0007-thin-market-means-distorted.md) 后果一节的同类理由）：`price` 的方向与取值域都变了，而「失败不覆盖」会让旧数据在抓取失败时原样留下、被新渲染层当成新数据——`0.2444` 会被读成「个/元」，**差十几倍且看起来完全正常**。指纹兜不住这条路径。
