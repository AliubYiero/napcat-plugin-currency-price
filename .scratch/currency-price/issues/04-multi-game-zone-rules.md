# 04 — 多游戏多区服与领域规则

Status: ready-for-agent
Type: AFK
Blocked by: 03
来源: [docs/design.md](../../../docs/design.md) §4 §5.4 §7.2 §8.1 §8.3 §16

## What to build

端到端行为是：`#currency price` 一次抓完默认三分区的 **10 个区服组合**并正确展示；某个区服组合挂掉时，它所属的**整个游戏**保持上一次的数据、只更新失败原因，别的游戏不受影响；配置里写错的通货名以「所有区服组合都找不到」的形式浮出来。

片 03 打通的是路径，这一片让它**在真实配置与真实失败模式下正确**。

要落定：

**铺开到默认三分区** —— 用设计文档 §5.4 的清单。三份 `currencyList` **彼此不通用，不要「顺手统一」**：同名通货跨游戏独立（见 `CONTEXT.md`），站点上各专区提供的通货本就不同——把流放之路2 的清单照抄给流放之路1，表现是**静默产出 0**（名称匹配不上, 不报错）。代码块里的注释是实测得出的领域知识，迁进配置时必须原样保留。

**区服层数随游戏而变**（流放之路 3 级、火炬之光 2 级），代码**不得假设固定层数**。

**游戏级原子性** —— 一个游戏内**任一区服组合**重试 3 次后仍失败 → **整个游戏本轮作废**，已成功读到的其他组合一并丢弃，只记 `lastError`。这是源项目三条硬约束中的「失败游戏不留半截数据」，**不得**为了「多保留一点数据」而改成部分成功。

**失败不覆盖** —— 游戏本轮失败 → `zones` / `readAt` 保持上一次成功的内容，只更新 `lastError`。因此 **`zones[]` 的每一项必定有 `prices`，永远不会有 `error` 字段**。

**游戏级 `readAt`** —— = 各组合 `readAt` 的最大值，是新鲜度判定的依据（判定逻辑在片 05）。

**`missing` 取交集而非并集** —— 不同区服提供的通货本来就不同（某通货可能只在国服有），所以「某个组合缺某通货」是**正常业务差异**。真正指向配置写错的信号是「**所有组合都缺同一个名字**」——这是唯一能让用户发现该类错误的途径，因为被过滤掉的行在消息里看不见。

**重试与耗时** —— 失败路径单组合最坏约 3 分钟；全部成功时秒级（实测 10 个组合的 `readAt` 总跨度约 9 秒）。别在这一片引入并发：现有抓取是多个游戏**共用同一个 page 串行**（UA 挂在 context 上，页面状态在组合间累积）。

## Acceptance criteria

- [ ] 三分区 10 个区服组合全部成功时秒级完成，各 `readAt` 的总跨度在秒级
- [ ] 人为让某游戏的一个区服组合失败（重试 3 次仍失败）→ 该游戏**整个**本轮作废，`zones` / `readAt` 保持旧值，只有 `lastError` 变化
- [ ] 同一轮里其他游戏的结果**不受影响**，正常覆盖
- [ ] `zones[]` 的每一项都有 `prices`，数据文件里**不存在**区服级的 `error` 字段
- [ ] 把流放之路2 的 `currencyList` 照抄给流放之路1 → 该游戏 `missing` 列出这些名字（而非静默产出 0）
- [ ] 某个通货只在部分区服存在 → **不**出现在 `missing` 里
- [ ] 火炬之光的 2 级区服与流放之路的 3 级区服在同一轮里都能正确抓取、存储与展示，代码无固定层数假设
- [ ] 游戏级 `readAt` = 该游戏各组合 `readAt` 的最大值
- [ ] 区服级 `readAt` 与游戏级 `readAt` 并存且各自独立
- [ ] `price: 0` 与 `price: null` 的语义区分在多游戏下依然保持
- [ ] 单轮抓取内不并发开页面（抓取期间进程里始终只有 1 个 page）
